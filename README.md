# Atlas

A RuneLite plugin for bank value, net-worth history, and session gains and losses. Track banked items, inventory, equipment, supported containers and your deployed cannon; browse and sort holdings, separate market movements from item changes, and optionally share completed history through your RuneLite account.

## Use it

1. Close the existing development RuneLite window.
2. In IntelliJ, reload the Gradle project if prompted, then run the `run` task in `build.gradle` as before. The launcher class is now `com.atlas.AtlasPluginLauncher`.
3. Log in and enable **Atlas** in the plugin list if necessary. Inventory/equipment update without a bank visit. Previously saved bank contents are restored for this character; if there is no saved bank, the display shows carried items only until you open the bank once.
4. Click the blue bar-chart icon in RuneLite's sidebar, then **Open dashboard / Net Worth**.
5. The **Items** tab provides icon cards, name search, ascending/descending sorting (stack GE, unit GE, stack HA, quantity, name), location selection and members/F2P/tradeability/quote filters. Hover an item for exact figures and its location breakdown. Items are paged in groups of 60.
6. The **Net Worth** tab shows selectable time ranges, GE/HA/unique-item history, and separate market/holdings effects. Hover the graph for timestamp and value. **Record snapshot** adds a point immediately; otherwise points are recorded every five minutes while logged in and on logout/shutdown.
7. **Value changed this session** shows the value of quantities gained/lost using fixed session prices, excluding market repricing. The sidebar's **Session History** button opens a list of completed logins and the current live session, newest first, with start/end timestamps, session time, signed value changes and change per hour. Hourly change uses the exact elapsed time from login to the last update/end and the same fixed-price item gains/losses; a zero-length session shows -- until a rate can be calculated. This also works for existing saved sessions. A badge just above the in-game backpack tab also shows that same current-session change: green for gains, red for losses, and white for zero. It uses compact text (for example, -1.16m) in a fixed 12-point bold font on a dark badge. The badge expands above the tab for longer values instead of shrinking or horizontally compressing the digits. It follows the visible fixed/resizable inventory tab and hides before the first session reading or while logged out.

The launcher uses RuneLite's documented Jagex development-login mechanism: https://github.com/runelite/runelite/wiki/Using-Jagex-Accounts . Never share the resulting credentials file; it is unrelated to this plugin's history files.

## What is counted

**Net worth = bank + main inventory + worn equipment + deployed cannon.** Notes are merged into their unnoted item; empty slots and placeholders are ignored. Counts, values and totals use 64-bit arithmetic. Coin/platinum values are 1/1,000 GP. The bank remains the last bank data the server provided. Open it again to refresh it, especially after activities that can change the bank indirectly.

**Cannon ownership:** the player's own `DROPCANNON` assembly state tracks the base, stand, barrels and furnace as they leave/return to inventory. Both regular and Shattered Relics ornamented pieces in the current client are supported. Observed item IDs and their existing quotes are retained, including a mix of variants; nearby players' cannon objects are not used. Setup and pickup therefore move owned quantities rather than creating a gain/loss. A conditional Deployed cannon line shows the value outside your inventory; All items and hover details include deployed pieces, while Bank/Inventory/Equipment filters show those locations only. Cannonballs, including granite cannonballs, are never added to deployed holdings: loading removes their inventory value, firing is not charged twice, and unused balls returned on pickup offset the original loading cost.

Deployed piece IDs are saved per character separately from loose bank quantities and restored after login/hopping. If the plugin first encounters an already-deployed cannon with no recorded skin, it estimates ordinary pieces and marks the session as estimated. Learning an unknown skin on pickup reconciles that sample rather than booking the correction as profit; simultaneous activity in that correction sample is not attributed. For an exact first test, start with the pieces in inventory before setup. A decayed/reclaimable cannon retains its tracked pieces; dropping/trading physical parts without an assembly-state change remains a loss. Packed GE sets and ornament kits are not deployed cannon pieces. Earlier history remains unchanged.

A bank visit is not required on every login, world hop, or plugin enable. Only bank quantities are restored from this character's saved data; old inventory/equipment quantities are discarded and replaced by live containers. Until a bank is observed in this session, the display labels the combined value **Estimated net worth** and shows when the bank was last seen. If the bank has never been recorded, current inventory/equipment are shown as **Known items only**, bank is **unknown**, and combined net-worth history is withheld. Samples are taken after inventory events settle, rather than independently for each moving item.

The plugin retains a copy of the last observed bank quantities while the bank is closed, even if RuneLite no longer exposes its bank container. New observations replace that copy. Bank changes are checkpointed to disk independently of graph sampling, so a recent withdrawal does not get restored in the bank and counted again in live gear after a restart. Session memory is reset on logout/hop/disable and only the newly selected profile's bank can be restored. If items moved while the plugin was off or in another client, that cannot be inferred from carried items alone; opening the bank refreshes the estimate without guessing whether those items were withdrawn or newly acquired.

Rune pouch contents are included using RuneLite's pouch type/quantity varbits and rune enum, including normal/divine and Trouver variants. The shared contents are counted once, in Inventory when a pouch is carried or Bank when it is banked. Empty slots and unowned pouches contribute nothing. Pouch-only changes are checked each game tick, so consuming runes does not require opening the bank or changing an inventory slot. Bank checkpoints keep loose bank quantities separate from pouch contents to avoid duplication after restart. Previous snapshots and completed sessions from before this fix retain their original figures; introducing pouch coverage can raise the graph total, while the new login session starts from the corrected baseline.

**Soul Bearer:** successful Fill/Bank-All and item-on-item sends credit the heads to the saved bank immediately, preserving their value until the next real bank refresh replaces that checkpoint. Initial-drop and bankable forms of all 23 supported head types share one holding. Session P/L expenses one blood rune and one soul rune per head actually removed, at the existing fixed session prices. Failed sends with no removal book no cost; partial batches cost only the heads sent. Observed paired rune loading and uncharging are neutral session transfers, so charging and then consuming a charge do not expense it twice. Inventory and bank Configure-Charges changes are supported. These adjustments affect session P/L and its hourly rate/badge; stored Soul Bearer charges themselves are not added to net worth or the net-worth graph. A matching action is required; changes made outside this client cannot be reconstructed. Remote heads sent before the first bank visit are retained as known partial holdings, without treating the whole bank as known. Open the bank once to establish the full baseline. Confirmation/quantity dialogues have a 60-second observation window.

Herb sack contents are tracked separately, including normal/open and silklined variants. Use **Check** once after login to synchronize the starting contents from the server's complete chat response. Confirmed pickup messages then add each herb live, even when no inventory slot changes. Previously saved counts are restored per character, but remain an estimate until checked because activity in another client cannot be observed. New pickups can be tracked before checking; unknown starting contents are not invented. Check reconciliations adjust net worth without booking old contents/corrections as current-session gains. Other activity in that same reconciliation sample is not attributed. The sidebar groups unconfirmed carried containers under "Check container to sync this session." with readable bullet names. Only containers currently in inventory appear; withdrawing or depositing a container updates the reminder, and checking it clears its bullet. Banked contents still contribute to valuation.

**Fill**, **Empty**, **Empty to bank**, and container deposit actions compare the sum of loose inventory + bank quantities. The destination is determined from those observed changes, not assumed from an English menu label. This fixes a contextual bank **Empty** action counting herb loot again. The bank's **deposit inventory** and **deposit containers** buttons share one transfer calculation, so overlapping containers cannot each consume the same bank delta. Clicking alone does not change counts; partial transfers only move observed quantities. Tracked contents follow containers into bank/inventory and remain separate from loose bank checkpoints. Item-on-item **Use** is supported in either direction: herb/seed/gem on its container, or container on the item. The selected and target item IDs identify the container, and only an observed decrease of the specific used item is transferred into storage. Pickup-looking chat confirmations are not counted a second time. A failed/full-container action adds nothing. Use **Check** again after unsupported changes such as death recovery, deposit-box transfers, missed messages, or actions outside this client. The plugin only observes events; it never clicks Check or sends game actions. Previously saved snapshots and sessions retain their original figures.

**Gem containers:** the gem bag, gem pouch, gem satchel, gem tote, and gem sack each have their own saved contents, including open/closed forms and their supported gem types/capacities. Check each carried container once after login. Explicit messages identify additions directly. Mining and matching your Take click to a ground-item removal can infer a gem entering a checked, open container with available room; a matching loose inventory gain or explicit addition is not counted again. These inferred additions mark the session as an estimate: another player taking an item, despawn timing, multiple overlapping open containers, or missed messages can make an inference wrong. Check to reconcile. When overlapping containers are partially emptied together, the combined quantity is conserved but each affected container requests another Check to verify the distribution. Single-use reward bags are not treated as reusable storage.

**Seed box:** supports open/closed forms, Check chat batches, confirmed direct-to-box pickup messages, and authoritative contents while its View interface is open. Fill/Empty transfers use the same combined loose quantities. Check or View it after login to confirm saved contents; old contents discovered on that first reading are not new session profit. Seed names are resolved through RuneLite's item cache, including spore/frag names when exposed by the game. Sources that produce neither a readable container update nor a supported message require another Check/View.

Unseen containers are not included: seed vault, POH storage, death storage, group storage, GE offers, looting bags, other pouches, quiver contents, and other storage. RuneLite item mappings may estimate charged/variant gear; these are not guaranteed liquidation values. The HA view is a simple sum of item high-alchemy values and cash, without rune cost, cast eligibility, or a promise that every item can actually be alched.

## Prices and change attribution

Prices use RuneLite's cached **GE guide** quotes (`getItemPriceWithSource(id, false)`), consistently, regardless of the user's global Wiki-price setting. They are not live transaction prices or sale proceeds. Updates depend on RuneLite's price refresh and may lag market trades. No new third-party data service or account is required.

For snapshots A and B:

- Market movement = sum of A's quantities × (B's unit price − A's unit price).
- Item changes = total net-worth change − market movement.

Removed/sold items are still re-quoted at B. This convention values changes in quantities at B's prices. Item changes can include loot, spending, trade gifts, death losses and supplies consumed; they are **not realized profit**. Quote availability/mapping revisions can also affect valuation. Missing quotes retain the previous recorded quote where available; items with no quote have zero GE value and are explicitly labelled. First capture waits for RuneLite's price list.

The graph compares actual recorded endpoints within the selected period, whose dates are displayed. Points can include cached bank contents, as disclosed in the dashboard; unavailable bank contents are never recorded as zero. No history is fabricated for days offline or before installation. There is no automatic daily 04:00 UTC snapshot when RuneLite is closed. Points, saved holdings and the latest bank checkpoint are stored locally, separately for each RuneScape profile (including distinct game modes), in the plugin's Filepath-managed directory using hashed profile filenames. They persist between launches. Files are atomically replaced where supported. Unreadable history pauses tracking and preserves the original. Older history files remain supported: their bank quantities are extracted from their last snapshot.

Cross-device history is available as an opt-in experimental RuneLite-account-sync prototype. It keeps local backups, merges completed sessions and graph points, and pauses rather than truncating data when the test budget is exceeded. A PC → Steam Deck → PC test confirmed automatic completed-session transfer on October 19, 2026, including a prayer-potion dose recorded as a roughly 2.4K GP loss on Deck and shown on PC. Long-term capacity and offline/concurrent use still need real-device testing; see [sync testing](SYNC-TESTING.md).

## Storage and settings

Atlas uses the `atlas` configuration group and the Filepath-managed `.runelite/plugin-data/atlas` directory. Each device creates its own device ID and character-specific history files. Cross-device sync is off by default; enable it on each device and sign into the same RuneLite account and OSRS character to share completed history. No separate Atlas account is required.

## Manual acceptance checks

### Login sessions

The session calculation is separate from the graph's market attribution. Each item's first available positive GE quote within the session is held fixed. The counter sums net quantity changes across bank + inventory + equipment + deployed cannon at those prices. An unchanged Twisted Bow falling 50M produces **zero** session loss; supplies consumed still produce a loss. New loot uses its first available quote. Later price changes do not revalue those gains, and gaining/losing the same item cancels even if its market price changed. Items without an available quote contribute zero until a quote becomes available.

A new baseline starts at the first valid live reading after login or enabling the plugin. A normal world hop does not split the session. Logout, client close or plugin disable saves the result through the last successful reading, which is also the displayed end time. The live entry is checkpointed when value changes and at least once per minute while sampled. If the process crashes or is force-killed, its next startup closes the previous entry as **Interrupted** at that last checkpoint; it does not fabricate an end time or join separate logins. This feature cannot reconstruct sessions from before installation.

Saved/unknown bank data makes a session an **Estimate**. The first actual bank observation rebases the holdings without assigning previously unseen bank contents or offline corrections as current-session profit/loss; activity simultaneous with that reconciliation sample is not added. Previously measured session gains/losses remain. Current holdings continue updating as before. Gifts, trades, purchases, consumables and deaths can all change owned quantities, so this remains an item-value-change estimate rather than a realized trading-profit ledger. Transfers into other untracked storage retain the limitations documented above.

- Relaunch away from a bank: the counter starts at zero after the first live reading and updates without visiting a bank.
- Equip/unequip and bank transfers keep the counter unchanged.
- Start with all cannon pieces in inventory and no cannonballs, then set up/pick up the cannon: total and session change stay steady, including partial assembly. Test the regular and ornamented versions. Load balls: only their value is lost; firing does not charge them again. Pick up with unused balls remaining: returned ammunition offsets its original loading cost. Log out/hop/restart while deployed, then pick up: no duplicate cannon gain. Check the conditional Deployed cannon line and item hover details.
- Pick up an ensouled head, then send it with Soul Bearer Fill and item-on-item Use in both directions. Session change should lose only one blood plus one soul rune per head sent; head value must remain in Bank, including after opening the bank, hopping and restarting. Test several head types in one batch, insufficient charges, a cancelled confirmation, ordinary head deposits/drops/reanimation, recharging from inventory/bank, and uncharging: failed sends cost nothing, and charge loading/refunds must not add another session cost or gain. Using fixture prices of 3,008 GP/head and 743 GP/charge gives +2,265 GP net after pickup/send.
- Move runes from bank/inventory into the rune pouch and back, including swapping rune types: net worth and session change remain stable at the same prices. Bank/withdraw the filled pouch and restart with it banked; contents must appear once. Cast a spell using pouch runes away from a bank: consumed runes reduce the session value without needing an inventory-slot change.
- Check the herb sack once after login, then pick up a grimy herb directly into the open sack. Inventory/net worth and session change should increase after the server confirmation without checking again. Fill/empty herbs and empty to bank: the total/session change should remain unchanged at fixed prices. Test partial emptying with limited inventory space, banking the filled sack, and relaunching with it banked. Check again to confirm saved counts without creating session profit. Existing Herb Sack Price Check output should remain unaffected.
- Use a 3,671 GP grimy Torstol on a herb sack: net worth and session change stay unchanged. Repeat in reverse and with a seed stack and supported gem, then empty into the bank. Test a full bag or cancelled action: no invented stored item. Use one herb while another disappears independently: only the used herb enters storage.
- Reproduce the reported regression: pickup is +2K; using contextual Empty or the deposit buttons must leave the session at +2K, not +4K. Depositing loose herbs while carrying a sack must not remove herbs still inside it.
- Check a gem container, then pick up/mine a supported uncut gem into its open form. Check again to confirm inferred counts. Test Fill, contextual Empty, full capacity (new loose gems must not also enter storage), partial emptying, and restart. Carry two variants with the same gem and use deposit containers; the gain must be booked once. Check individual bags after an ambiguous partial bulk transfer.
- Check/View a seed box, pick up seeds directly into it, then Fill/Empty/empty to bank. Transfers preserve total/session value, while new pickups add value once. Reopen View and restart to confirm stored counts remain per character.
- Acquire an item or consume a supply: the counter respectively increases/decreases at its fixed session quote.
- Check **Session History**: current session is marked Live. Log out and back in; the previous row is saved with the last update time and the new counter starts at zero.
- Hop worlds: keep the same session rather than adding a completed row.
- Compare the backpack-tab number with Value changed this session: gains are green, losses red, zero white. Test switching tabs, fixed/resizable layouts and window resizing; the text follows the backpack tab. Logout clears the old value and the next login uses the new session baseline.
- Existing net-worth graph and item list continue working, and earlier saved wealth data still loads.

### Wealth totals

- First-ever login with no saved bank: live inventory/equipment and **Bank unknown**; no combined-history point until the bank is first opened.
- Returning login away from a bank: saved bank contents plus live inventory/equipment, with an estimated label and last bank observation time. Equip/unequip, acquire loot or use a supply before visiting the bank; carried values should change immediately after settling.
- Bank sync: net worth equals the three displayed location totals; placeholders add nothing.
- Withdraw a valuable item, equip it, unequip it and deposit it: combined value remains unchanged at the same quote; location breakdown changes. Repeat with notes.
- Specifically close the bank and walk away before equipping/unequipping the withdrawn item: inventory/equipment totals must update within a few seconds without reopening the bank, and the bank total stays at its last observed value. Swapping weapons must also account for the weapon returned to inventory.
- Search/sort/filter/page through items; verify exact values in hover text.
- Record two snapshots: a visible point/line and correct timestamps should appear in Net Worth.
- Restart: this account's history remains and live carried values resume without opening the bank. A different character must not see this account's data. Withdraw gear and restart before the next five-minute sample: the newer bank checkpoint must prevent double counting.
- Reopen the bank after indirect bank changes. Missing storage/charges are disclosed limitations rather than silently counted as known assets.

Automated arithmetic/storage checks do not establish in-game correctness; the player must confirm the behavior above.
